## Stack (decided)
Vite + Preact + @preact/signals, TypeScript `strict` (plus noUncheckedIndexedAccess), ES modules, no other runtime dependencies. No jQuery/Vue/Modernizr/FastClick — sliders, drags and transitions are your own small components (pointer events). Hand-written CSS with custom properties (new, tokenized, a fraction of the legacy 4.7k lines) — use the legacy CSS as the source of exact values (sizes, colours, spacing, easing `cubic-bezier(.18,0,0,1)`, the 620px compact/wide breakpoint, the 800x480 rules), do not paste it wholesale. Reuse the legacy monochrome symbol SVGs (CSS mask colouring) and the Metropolis font (only the weights actually used; verify its licence from the font's upstream and record it); record third-party notices in `ui/THIRD-PARTY.md` (B&O Create MIT, Metropolis). Do NOT use B&O logos, product photos, or the names "Beocreate"/"Bang & Olufsen"/"Beo…" anywhere in the UI or identifiers.
Build: `npm run build` -> `ui/dist/index.html` (must contain `<meta name="audio-os-ui">`) referencing only `/ui/...` URLs, with all assets under `ui/dist/ui/` (Vite `assetsDir: 'ui'`; hashed names). No external requests at load. Budget: JS ≤ 60 kB gzip, first paint must not wait for the network. npm scripts required: `dev`, `build`, `typecheck`, `test` (unit + Playwright), `test:unit`, `test:e2e`.

## Product (decided)
Same structure and feel as the reference: top tab bar in wide layout / dark slide-in menu in compact; a permanently dark bottom player bar (open-chevron, source icon, title + artist, mute icon, volume slider, volume icon); full-screen Now Playing that slides/fades over everything (artwork left, title/artist/album right, dark transport strip with previous / play-pause / next + volume, source name in the header) — match kiosk-nowplaying-playing.png closely; light and dark via prefers-color-scheme.
Screens:
- **Now Playing** — live from ACR (REST snapshot on connect, then WebSocket events; resync on every reconnect). Transport buttons shown per the active player's current capabilities. Position/duration progress only if it fits the reference look (thin, unobtrusive). Idle state like the reference when nothing plays. Artwork: fade between tracks, neutral placeholder when absent or on load error.
- **Sources** — ACR's players with friendly names + icons (map by player name: librespot→"Spotify Connect", shairport→"AirPlay", bluetooth→"Bluetooth", mpd→"Radio & music", raat→"Roon", unknown→ its name), the active/playing one marked as in kiosk-sources.png. Tapping a row plays/pauses that player when its capabilities allow; otherwise show a one-line hint (e.g. "Choose this speaker in the Spotify app").
- **Radio** — favourites from `GET/PUT /api/device/v1/radio` (tap to play; remove). Search stations through radio-browser.info directly from the browser exactly as upstream's own UI does (see scratchpad/ref/hbos-ui/src/stores/radio.ts and src/api/player.ts for server discovery, search call, and the ACR command sequence used to start a stream on player `mpd`: optional m3u parse, pause current player, clear_queue, add_track with metadata, play) and add to favourites. On the kiosk (no keyboard) hide search and show a hint to add stations from a phone at the device's address.
- **Screen** — only when `GET /api/device/v1/screen` says available: brightness slider (send on change, debounced ~300 ms, final value on release) and "turn screen off after" choice (1 min, 5 min, 30 min, 2 h).
- **System** — name, model/sound card, IP/network (configurator `GET /api/config/v1/systeminfo` and `/network`; read scratchpad/ref/configurator source for the real response shapes), software version (`/api/device/v1/info`), Restart and Shut down via `POST /api/device/v1/power` behind a confirm dialog styled like the reference `.ask` dialogs, then a "restarting…/you can unplug in a moment" overlay that recovers when the device is back; "Advanced settings" (upstream's own UI at `/services`): a normal link on phones/desktops, on the kiosk a text hint with the device address instead (the kiosk has no keyboard and no way back).
- Kiosk mode = page loaded from `localhost`/`127.0.0.1`: start on Now Playing; return to Now Playing after 60 s without interaction while something is playing; no text selection, context menu, or zoom; touch targets ≥ 44 px.
- Auth: everyday calls never need a password. If a call returns 401, read the `WWW-Authenticate-Hint` header and show a small password sheet: "set-password" -> `POST /api/auth/set-password`, otherwise login; then retry with the CSRF token. Read the real service (scratchpad/debs-web/x/hifiberry-auth/…/hifiberry_auth/server.py) for exact endpoints, bodies, cookie and `X-CSRF-Token` behaviour.
- Connection: a clear, calm "Connecting…" state while the backend is unreachable (the device shows the UI during boot before the audio service is up, and during the one-time first-boot reboot); exponential backoff reconnect capped at ~5 s; never show stale "playing" state after a disconnect. One failing backend (helper, configurator) must degrade only its own screen.
- Volume: slider reflects ACR volume events; while the user drags, the user's value wins; sends are throttled (~10/s) with the final value always sent; `available:false` or failures disable the slider without ever showing 0.

## Code quality
Small modules with one job each: a typed API layer (one file per backend: acr, device, config, auth, radio-browser) that validates what it receives at the boundary (hand-written narrow type guards — no blind casts of network JSON), a store (signals) with pure reducers for ACR events that are unit-tested, presentational components. No `any`, no non-null `!` on network data. Escape nothing by hand (Preact does) and never use dangerouslySetInnerHTML. Station names/artwork URLs/metadata are untrusted: only http(s) image URLs. File headers per FACTS engineering rules.
